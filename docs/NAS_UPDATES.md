# Synology / NAS Update Dry Run

The deployment adapter is an operator CLI running on the NAS host. The web/API containers do not mount `/var/run/docker.sock`. Install the PDI CLI in an operator-controlled environment that can reach the PDI PostgreSQL database and Docker CLI, and protect that account as root-equivalent. Before executing a prepared update, replace that helper with the exact target backend digest from the validated release manifest. The target helper is part of the immutable release identity and may contain the constrained service allowlist and verification order required by that release.

The Compose base, NAS override, environment file, and managed image overlay paths are configurable command arguments. Their ownership and the confirmed NAS port and storage topology are defined in [NAS_DEPLOYMENT.md](NAS_DEPLOYMENT.md). Stage the target release's Compose definitions without recreating the running stack, and include every PDI application service in the managed overlay while still pinning the currently installed exact digest. The executor resolves each path, validates Compose, fixes the project to `pdi`, restarts only its mandatory API, worker, scheduler, and web allowlist, and accepts only official backend/web images at exact digests. PostgreSQL is never stopped. No service outside the PDI project is addressed.

For the initial dry run, copy `deploy/compose.update-managed.json` beside the NAS Compose files and ensure its seven entries (`api`, `worker`, both schedulers, `consume`, `mail`, and `web`) equal the currently deployed RepoDigests, including services that are not running. Add it last in every normal NAS Compose invocation so reboot/recreation retains immutable pins. Record enabled optional profiles before an update and restart only those profiles afterward. Run the command in [UPDATES.md](UPDATES.md) with `--dry-run`; it validates configuration and state but does not pull, write, stop, migrate, or start anything.

Keep `.env.release` outside source control. The UI never edits it. Executor output and the update journal contain no environment contents, tokens, passwords, host paths, document text, or registry credentials. Do not capture raw `docker compose config` output because Compose expands secret-bearing environment values; use targeted service and image queries instead.
