# PDI v1.4.0

PDI v1.4.0 completes the roadmap from daily ingestion through Paperless full-cutover readiness. It is the final program release candidate for the next operator-controlled NAS deployment; this release process does not deploy it.

## Highlights

- Production-quality consume-folder and read-only IMAP ingestion with durable source health, stable-file safety, duplicate handling, explicit retry, and scanner guidance.
- Validated and audited administration of safe runtime policy without exposing deployment secrets or arbitrary environment/command settings.
- More precise German document intelligence with measured classification, extraction, deadline, contract, organization, and proposal-noise budgets.
- Structured PostgreSQL search with composable filters, facets, saved searches, knowledge links, and ranking regression budgets. Semantic/vector search remains deferred because it did not justify mandatory new infrastructure.
- Restart-safe in-app deadline reminders with configurable lead times, evidence links, and explicit lifecycle actions.
- Resumable Paperless preservation with originals, archives, legacy OCR, metadata/provenance, source reconciliation, exact verification, backlog controls, and bounded large-library performance.

## Upgrade path from v1.2.0

PDI v1.2.0 has no Update Manager. Perform the already qualified, backup-first, digest-pinned manual bootstrap to v1.3.0 and verify readiness, search, storage, authentication, and schema. From v1.3.0/schema `20260828_0015`, stage the v1.4.0 Compose definitions and expanded current-digest overlay, update the operator helper to the manifest's exact v1.4.0 backend digest, and use the Controlled Update Manager to install the exact immutable v1.4.0 images, migrate to `20260828_0020`, start the new scheduler services, rebuild the search projection before full readiness, and complete blocking verification. The accumulated direct database upgrade remains forward-only from `20260826_0013` through `20260828_0020`; rollback requires coordinated backup restore.

## Paperless cutover boundary

The release makes PDI ready to preserve and verify a full Paperless library, but never stops, deletes, or writes to Paperless. Actual cutover still requires an operator-approved final source inventory, verified Paperless and PDI backups, a zero-blocker analyze/dry-run/import/verify sequence, and a retained read-only validation period.

## Final release-candidate qualification

The official v1.3.0→v1.4.0-rc.4 update completed from a clean disposable stack using the release manifest's exact image digests. It preserved both synthetic documents and hashes, migrated schema `20260828_0015` to `20260828_0020`, rebuilt and verified search, reconciled storage, retained and independently verified the coordinated rollback backup, and produced the exact deterministic twelve-stage audit journal without recovery replay.

A full stop/start of PostgreSQL, API, worker, backup scheduler, reminder scheduler, web, and their persistent volumes preserved authentication, document identities, search, storage, schema, backup verification, and the completed journal. RC4 is therefore the qualified code candidate for the final v1.4.0 tag; no production NAS or Paperless system was accessed during qualification.

## Deferred intentionally

Atlas, Compute Core, embeddings/vector infrastructure, external notification delivery, and unattended patch installation are not part of v1.4.0. Their ownership and decision gates are recorded in `docs/FUTURE_ROADMAP.md`.
