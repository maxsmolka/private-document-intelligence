# PDI v1.1.2

PDI v1.1.2 adds a secure browser-based first-run experience and includes the reviewed A1 architecture hardening checkpoint.

## Highlights

- Fresh zero-user installations redirect to a concise `/setup` wizard.
- First-admin creation is server-authoritative and serialized in PostgreSQL; concurrent requests create exactly one active Admin.
- Successful setup issues the same normal session and CSRF cookies as ordinary authentication.
- Optional authenticator enrollment reuses the existing encrypted TOTP, verification, and one-time recovery-code lifecycle.
- Headless/operator `pdi user create` remains supported through the shared bootstrap service.
- A1 removes the core ORM cycle, closes canonical mutation races, bounds search maintenance, removes a Knowledge Review N+1, and adds architecture/performance guardrails.

## Security and deployment

Keep PDI on a private network or VPN behind HTTPS. A fresh host reachable by untrusted clients can be claimed before the operator; set `PDI_SETUP_ENABLED=false` and bootstrap through the CLI in that deployment model. Browser setup still requires zero users and an allowed `Origin`. It cannot generate or persist `PDI_TOTP_ENCRYPTION_KEY`.

Configure `.env.release`, start the exact versioned images, open the PDI URL, and follow `/setup`. Existing installations with any user never enter setup and continue unchanged.

## Compatibility

- Alembic remains `20260826_0012`; no migration is required.
- No search reindex is required.
- Document, storage, backup, export, API, user, role, session, token, TOTP, recovery-code, and audit formats are unchanged.
- No production NAS access is part of release preparation.
