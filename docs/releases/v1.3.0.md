# PDI v1.3.0

PDI v1.3.0 completes the Controlled Update Manager milestone. It adds a reviewable, backup-gated, digest-pinned update path without granting Docker access to the main API or enabling unattended installation.

## Highlights

- Discover and validate signed-by-release-process manifests from the official repository.
- Plan and prepare updates with blocking readiness, storage, search, schema, execution, authentication, and capacity checks.
- Create and verify a coordinated backup linked to the update run before installation.
- Drain active work through durable A2 state and keep queued work intact.
- Execute host mutation through a constrained operator CLI that controls only known PDI services and official image repositories.
- Verify exact image digests, OCI version/revision labels, Alembic head, service startup, readiness, search, storage, and execution state before completion.
- Retain a sanitized, durable transition history and require backup restore instead of blind destructive replay after an interrupted migrated deployment.

## Qualification evidence

The official RC5 manager installed the official immutable RC6 target in a disposable stack. The run completed on schema `20260828_0015` with its verified backup linked, exact images and release labels present, maintenance disabled, and the executor lease cleared. Its 12-stage history contained no crash-recovery event. A complete stack restart preserved the same terminal history, authenticated session, document IDs, hashes, extraction selection, search index, and storage integrity.

Failure tests cover backup, drain, pull, digest/revision, migration, startup, readiness, search, and storage failures. Browser disconnect does not own execution, and helper/API restart tests prevent automatic destructive replay.

## Adoption from v1.2.0

PDI v1.2.0 does not contain the manager. Its first transition to v1.3.0 is therefore the documented manual, backup-first, digest-pinned bootstrap. Once v1.3.0 is installed and verified, later manifest-bearing releases can use the Controlled Update Manager.

Prerelease discovery and automatic installation remain disabled by default. This release was qualified without accessing or changing the production NAS or Paperless service.
