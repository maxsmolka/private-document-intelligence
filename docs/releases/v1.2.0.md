# PDI v1.2.0

PDI v1.2.0 introduces a durable, resource-aware execution architecture while preserving document-domain ownership and the v1.1.2 first-run setup flow.

## Execution architecture

- Deterministic priority scheduling with stable tie-breaking and starvation aging.
- Resource-aware admission with durable cross-worker concurrency limits for expensive work.
- Cooperative cancellation, explicit execution and provider timeouts, classified failures, bounded retry policies, and lightweight predecessor dependencies.
- Crash recovery through database-authoritative claims, heartbeats, and stale resource-lease cleanup.
- Sanitized execution journals, administrator diagnostics, exact queue/resource counters, and measured scheduler performance budgets.
- Explicit executor capabilities and a narrow future adapter boundary. **Compute Core is not integrated.**

## Compatibility

- Existing documents, assets, extraction and intelligence history, review decisions, canonical knowledge, search projections, users, sessions, API tokens, TOTP configuration, and recovery codes are preserved.
- The browser first-run setup and headless bootstrap paths remain unchanged and do not depend on the worker.
- No document reindex is required.

## Migration and rollback

- Alembic migration `20260826_0013` adds typed execution metadata, cancellation/failure state, scheduling indexes, journal fields, and durable resource leases.
- Create and verify a complete PostgreSQL and document-storage backup before upgrading.
- A simple image downgrade is not supported after schema 0013. If rollback is required, restore the verified pre-upgrade backup and then start the previous release.
