# PDI v1.4.1

PDI v1.4.1 is a maintenance and operations patch for the v1.4 production baseline. It does not add v1.5 functionality and does not change the database schema or search representation.

## Highlights

- Hardens the documented NAS deployment baseline, including the Synology web-port override, Compose ownership, optional-profile lifecycle, shared document-storage requirement, consume permissions, and secret-safe diagnostics.
- Prevents optional PDI services from silently running stale application images by extending immutable backend-digest management to `consume` and `mail` alongside API, worker, and both schedulers.
- Keeps optional profiles opt-in: the constrained update executor continues to restart only the five mandatory core services.
- Records the production-tested consume handoff and OCR behavior while distinguishing source archival in `processed` from later worker and OCR completion.
- Aligns active documentation with the v1.4 maintenance baseline and records the v1.5–v1.8 roadmap without implementing future features.
- Makes Review queue regression coverage deterministic for the defined oldest-creation-then-document-ID ordering.

## Upgrade from v1.4.0

The schema remains `20260828_0020`; no Alembic migration and no search reindex are required. A verified coordinated backup remains mandatory. The release manifest uses image-only rollback because the patch changes neither database nor storage format. Apply the managed overlay last so all six Python services resolve to the same v1.4.1 backend digest and web resolves to the matching web digest. Optional `consume` and `mail` profiles remain stopped unless the operator explicitly re-enables profiles that were active before maintenance.

The production NAS is not updated by this release process. Installation remains a separate operator-controlled action.
