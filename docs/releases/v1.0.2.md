# PDI v1.0.2

PDI v1.0.2 is a focused processing-reliability, review-integrity, and deterministic-intelligence quality release.

## Reliability and review

- A parseable PDF whose OCR provider times out, is unavailable, or fails now completes into review with explicit degraded-stage, component, reason, and retryability provenance. Corrupt originals and configured safety-limit violations remain hard failures.
- Reject is proposal-scoped, durable, and audited for every knowledge proposal type. It never requires evidence verification and never mutates canonical knowledge. Acceptance and editing retain their evidence gate.
- Document completion and proposal decisions update local review queues and counters immediately, then refresh server data in the existing Next.js architecture.
- User creation no longer sends a password-tainted user object into generic CLI output; it reports only the normalized non-secret username.

## Deterministic intelligence

- German invoice phrases including `zahlbar bis zum`, `begleichen Sie den Rechnungsbetrag bis zum`, and `fällig am` produce grounded payment deadlines and payment-due events. Invoice identifiers and amounts alone no longer propose contracts.
- Annual Riester value statements classify as pension statements in the existing insurance life area. Document date, valuation date, contract start, planned retirement start, product, monthly contribution, retirement assets, and cancellation value are typed separately.
- Percentage-based model and scenario lines are excluded from current-value candidates. All emitted candidates retain the existing evidence and IntelligenceRun provenance.

## Compatibility

- No Alembic migration, backup-format change, storage-format change, mandatory reindex, or storage reconciliation is introduced.
- The intelligence result schema advances to version 2; existing version-1 runs and accepted/rejected proposal rows remain readable and unchanged.
- Upgrade and rollback are application-image changes only, but a verified pre-update database and storage backup remains required operational policy.

## NAS update verification

Deploy exact immutable `1.0.2` image digests, not `latest`, using the established preflight and verified-backup workflow. After startup:

```bash
docker compose --env-file .env.release -f compose.release.yaml ps
docker compose --env-file .env.release -f compose.release.yaml exec -T api pdi readiness
docker compose --env-file .env.release -f compose.release.yaml exec -T api pdi search verify
docker compose --env-file .env.release -f compose.release.yaml exec -T api pdi storage reconcile
```

Then verify login, one existing document, search, document review, knowledge review, and a synthetic disposable upload through the HTTPS application. No production NAS access was used while preparing this release.
